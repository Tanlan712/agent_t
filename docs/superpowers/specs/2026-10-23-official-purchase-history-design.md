# 錢包紀錄：匯入 Riot 官方購買紀錄（手機 App）— 規格草稿（2026-10-23，待使用者確認）

使用者 2026-10-23 選擇「嘗試抓官方頁的資料」。本文件先說明做法與風險，**使用者確認前不實作、不改 AGENTS.md**。

## 背景
- Riot 沒有公開儲值／購買紀錄的 API；遊戲 token（pd／glz）讀不到。
- 官方紀錄在客服網站：`https://support.riotgames.com/zh-tw/valorant/billing/checking-your-purchase-history`，
  要在該網站用 Riot 帳號另外登入，紀錄只顯示在網頁上。
- 網頁版（GitHub Pages）讀不到別的網站內容（瀏覽器的同源限制），所以**只做手機 App**（Android APK／iOS）。

## 做法
1. 錢包紀錄頁加「匯入官方購買紀錄」（只在手機 App 顯示；網頁版維持「查看官方購買紀錄」按鈕開新分頁）。
2. 按下後開一個 App 內的內嵌頁，**只允許** `support.riotgames.com` 與 Riot 登入頁（`auth.riotgames.com`／`authenticate.riotgames.com`）；
   其他網址一律擋下。使用者自己登入、自己捲動到購買紀錄。
3. 頁面底部有「匯入這頁的紀錄」按鈕。**使用者按下時**才執行一段固定的唯讀 JavaScript，
   只讀購買紀錄表格的文字（日期、品項、VP 數量、金額），回傳給 App。
   - 不讀 cookie、localStorage、表單、帳號資料；不自動點擊、不自動翻頁、不在背景執行。
   - 讀不到表格時顯示「找不到購買紀錄，請確認已登入並打開紀錄」。
4. 解析出的紀錄存在這台手機（依 puuid 分帳號，`purchase_history_v1`），錢包紀錄頁顯示：
   官方紀錄的總儲值 VP／總金額、每筆紀錄，以及原本的「本機記錄的餘額變化」。可以清除。
5. 不送到任何伺服器，不寫 log（只記錄筆數）。

## 要改的規則（AGENTS.md）
- §3 內嵌頁目前寫「不得注入或執行任何 JavaScript」。改為：
  **唯一例外**是 `support.riotgames.com` 的購買紀錄頁，由使用者按「匯入」時執行固定的唯讀腳本，只讀紀錄表格的文字；
  登入頁仍然完全不注入。仍然不得讀取或保存 cookie。
- §3 錢包那一列補上使用者決定（2026-10-23）。

## 風險（要如實告知使用者）
- **服務條款**：這等於讓程式讀 Riot 網站的內容（爬網頁）。雖然是使用者自己登入、自己按、只讀一次自己的資料，
  仍比目前只呼叫遊戲 API 更容易被 Riot 視為自動化；最壞情況可能影響帳號。實際風險低，但不是零。
- **會壞**：Riot 改版客服網站，解析就會失效，要再修。
- **格式未知**：雲端環境不能登入你的帳號，看不到紀錄表格長什麼樣子。第一版會先用寬鬆的方式找表格；
  需要你在手機上實測一次，再把「看到的欄位名稱」（不必給金額）告訴我來調整。
- **可能載不出來**：客服網站可能要求兩步驟驗證、或在內嵌頁裡被擋（例如 Google／Apple 登入不能在內嵌頁用）。
  那時只能退回「查看官方購買紀錄」按鈕。
- 紀錄含有金額與購買時間，存在手機上；手機被別人拿到時看得到。

## 測試
- 單元測試：用假的表格 HTML／文字測解析（不含真實資料）。
- widget 測試：網址允許清單、按「匯入」才執行腳本、腳本內容不含 `cookie`、`localStorage`、`fetch(`、`.click(`。
- 實機：使用者在 Android APK 實測後回報。
